## Сохранения и перенос между адресами

Состояние игроков хранится только в их браузерах: IndexedDB `last-city` / `world` / `last-city-v1`. Другой домен/протокол/порт имеет отдельное хранилище; автоматическое чтение старого origin запрещено браузером. Очистка данных сайта/инкогнито/другой браузер могут лишить локального слота.

Безопасный ручной перенос:
1. На старом сайте поставить паузу и «Мир» → экспорт JSON. Убедиться, что файл скачан, сохранить копию отдельно.
2. Если на новом сайте уже есть мир, экспортировать и его. Импорт v0.2.20 заменяет текущий слот без отдельного подтверждения.
3. На новом сайте «Мир» → импорт, выбрать копию. Сверить бункеры, людей, ресурсы, задания. Перезагрузить и снова проверить.
4. Не удалять исходные JSON и данные старого сайта до проверки. Сохранение с новыми схемами может не читаться старой версией; перед обновлениями сохранять файл старого формата.

Импорт ограничен 20 MB, restore валидирует формат. Исторические флаги `unexploredResetV18`, `bunkers234CleanupV17`, `bunker2CleanupV15` предотвращают повторные очистки. Не удалять/сбрасывать их. В storage.js есть резервные ключи `before-unexplored-reset-v18`, `before-bunkers234-cleanup-v17`, `before-bunker2-cleanup-v15`. UI экспортирует первую из этих копий. Старые сохранения без флагов проходят историческую очистку: сначала обязательно сохранить оригинальный JSON. Не утверждать, что любой старый импорт совершенно без потерь.

Следующее улучшение безопасности импорта: транзакционно разобрать и проверить кандидата, сохранить текущий слот в отдельную копию, запросить подтверждение замены, затем заменить. В этой передаче логика импорта не переписана.
