# Проверки

## Автоматически

```sh
npm test
npm run check
npm run build
```

`tests/*.test.js`: симуляция, строительство, экономика, маршруты, бункеры, тоннели, миграции/сериализация, UI-контракты. Это Node-тесты, а не полноценная проверка DOM, IndexedDB и touch в браузере. `scripts/check.mjs` проверяет синтаксис, относительные зависимости, наличие файлов и воспроизводимость автономной сборки. CI: стандартный Linux runner, Node 22, без npm install. Pages запускает эти проверки до публикации.

## Ручной desktop / Android Chrome

Использовать отдельный профиль/тестовый origin и экспортированные копии, никогда не сбрасывать настоящий мир.

1. Открыть HTTPS-сайт, проверить v0.2.20, отсутствие ошибок/пустого canvas, читабельность при горизонтальной и вертикальной ориентации.
2. Перетащить карту, pinch на Android, масштаб кнопками. Нажатие после drag не должно строить.
3. Выбрать стройку и доступную комнату; ресурсы списываются один раз, строитель идёт и завершает работу. Проверить лестницу между этажами и раскопку; недоступная клетка выдаёт понятную причину.
4. Выбрать лестницу, скрыть UI, нажать клетку: **известный FAIL v0.2.20**, ожидается исправление B. Проверить возврат UI и отсутствие невидимых touch-перекрытий.
5. На подготовленной тестовой кампании изучить 600 клеток, проложить проход к краю; начать тоннель. Рабочий идёт, прогресс ждёт прибытия, сосед появляется только в конце, мини-карта переключает бункер. Надпись может перекрывать человека — задача A.
6. Основание нового бункера: 5 переселенцев, комплект, груз в пути; проверить отдельные запасы и отсутствие дубликатов людей.
7. Пауза → сохранить → экспорт JSON → перезагрузка → сверить людей, ресурсы, задания, active bunker. На другом origin импортировать копию и сверить снова. Проверить сохранение середины тоннеля. Невалидный файл должен показывать ошибку.
8. Проверить производительность 1×/3×/8×, паузу, фон/возврат, разрешение Android на скачивание JSON. Не обещать симуляцию в выгруженной ОС вкладке.
